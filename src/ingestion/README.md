# Data Ingestion

This directory contains the canonical dataset-assembly stage used to create the finalized CSV files under `data/ingested/`.

## Submission role

The **final ML pipeline starts from the already-generated files in `data/ingested/`**. Therefore, you do **not** need to run this directory before training or evaluating the submitted models.

The ingestion code is included for provenance and reproducibility of the earlier data-assembly stage.

The historical data flow is:

```text
raw PCAP / auxiliary data
        |
        v
src/extraction/
        |
        v
data/extracted/
        |
        v
src/ingestion/
        |
        v
data/ingested/
        |
        +--> final preprocessing
        +--> feature engineering
        +--> models
        +--> hybrid pipeline
        +--> LLM arbitration
```

Raw-PCAP extraction and the intermediate `data/extracted/` files are not required to reproduce the reported model results when the finalized `data/ingested/` CSVs are supplied.

## Directory contents

```text
src/ingestion/
├── README.md
├── __init__.py
├── data_ingestion.py
└── ingestion_config.py
```

### `ingestion_config.py`

Defines portable project-relative paths for:

- the aligned extraction directories under `data/extracted/`;
- the finalized outputs under `data/ingested/`;
- the canonical metadata fields required during ingestion.

No machine-specific absolute path is used.

### `data_ingestion.py`

Builds the three canonical datasets:

```text
data/ingested/dataset1_ingested.csv
data/ingested/dataset2_ingested.csv
data/ingested/dataset3_ingested.csv
```

For every aligned extraction CSV, the ingestion stage:

1. cleans CSV header whitespace/BOM markers;
2. validates the required canonical columns;
3. enforces one exact column schema and ordering across D1/D2/D3;
4. parses and validates every `Timestamp`;
5. assigns the authoritative binary class label from the benign/malicious input directory;
6. creates `SourceFile` provenance in the form `benign/<file>.csv` or `malicious/<file>.csv`;
7. sorts flows chronologically within each `SourceFile`;
8. combines benign and malicious flows within each dataset;
9. verifies that every dataset contains both classes and that each `SourceFile` is class-pure;
10. verifies that Dataset 1 includes the aligned CIC-IDS2017 Friday benign HTTPS source;
11. writes the finalized ingested CSVs.

## What ingestion deliberately does not do

This stage does **not**:

- split data into TRAIN / VALIDATION / TEST;
- fit imputation statistics;
- replace or impute missing numeric values;
- apply signed-log transformation;
- fit or apply RobustScaler;
- remove constant/redundant features;
- perform correlation/RMI feature selection;
- remove identifiers required by later grouping or sequencing;
- construct LSTM/LITEMV sequences;
- train any model;
- select any decision threshold.

Those operations occur only in the appropriate downstream pipeline stages.

## Rebuilding `data/ingested/`

This is optional for the final submission.

If the aligned extraction outputs are available in the expected `data/extracted/` directories, run from the project root:

```bash
python src/ingestion/data_ingestion.py
```

The script rebuilds all three canonical ingested datasets.

It can also be imported as a package module by code that needs its utility functions.

## Required intermediate inputs

Rebuilding requires the aligned extraction directories:

```text
data/extracted/
├── dataset1/
│   ├── benign_cicflowmeter_aligned/
│   └── malicious_cicflowmeter_https_aligned/
├── dataset2/
│   ├── benign_cicflowmeter_https_aligned/
│   └── malicious_cicflowmeter_config_aligned/
└── dataset3/
    ├── benign_cicflowmeter_https_aligned/
    └── malicious_cicflowmeter_config_aligned/
```

Dataset 1's benign directory must include:

```text
friday_benign_https_aligned.csv
```

These intermediate files are generated by `src/extraction/`.

## Final-model execution

If the submission already contains:

```text
data/ingested/dataset1_ingested.csv
data/ingested/dataset2_ingested.csv
data/ingested/dataset3_ingested.csv
```

then **do not run ingestion first**.

Proceed directly to the final preprocessing / model / hybrid entry points documented elsewhere in the repository.

## Dependencies

This stage requires Python and pandas. The exact project environment is documented in the repository-level `requirements.txt`.

## Leakage boundary

Ingestion is deliberately performed before model-specific splitting and does not learn any statistical transformation from the data.

`SourceFile`, timestamp, endpoint, and identifier fields are retained only because downstream stages may require them for source-aware splitting, temporal ordering, endpoint grouping, or forensic provenance. Their predictive use is controlled by the downstream feature/model implementations.
